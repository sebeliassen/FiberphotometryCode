#### The Memory vs. Wall-Clock Time Trade-off
Batching in iterative Gibbs sampling exhibits two distinct failure modes:

```text
▲ Time per Iteration (Seconds)
│
│   PCIe & Dispatch Latency Wall             Optimal Operating Window          VRAM Allocation OOM
│   (Thousands of Host-Device transfers)     (High GPU Occupancy, low copies)  (VRAM > 24 GB)
│
│80s│  ● bs=2 (~72.6s/iter)                                                         
│   │   \                                                                           
│40s│    \                                                                          
│20s│     \____                                                                     
│10s│          ● bs=10 (AR: ~5.5s) ─── ● bs=20 (SLDS: ~12.3s)                      
│ 0s└───┴──────┴───────────────────────┴───────────────────────────────────────┴──────► Batch Size
│      bs=1   bs=10                   bs=20                                  bs=58+ (OOM!)
```

* **Ultra-fine batching ($bs=1$ or $2$):** Eliminates memory pressure ($6.2\text{ GB}$ VRAM), but creates a **PCIe bus bottleneck**. Transferring 1,851 sequences across 6 Gibbs sub-steps incurs $\sim 926$ host-device transfers per step, exploding iteration time to **$72.6\text{s/iter}$** ($>11\text{ hours}$ for 250 iterations).
* **Coarse / Unbatched ($bs \ge 58$ or $1,851$):** Maximizes compute utilization, but JAX XLA materializes monolithic intermediate broadcast buffers ($(N, T, K, D) \approx \mathbf{14.0\text{ GB}}$ in AR emissions, and $(N, T, K_p) \approx \mathbf{3.4\text{ GB}}$ in SLDS noise scales), exceeding the 24.5 GB VRAM limit and crashing with `RESOURCE_EXHAUSTED`.
* **Engineered Sweet Spot ($bs=10$ for AR, $bs=20$ for SLDS):** Uses CPU zero-copy NumPy slicing and host-pinned streaming concatenation. Keeps peak VRAM at **$16.8\text{ GB}$** while maintaining an iteration speed of **$5.5\text{s}$ (AR)** and **$12.3\text{s}$ (SLDS)** ($\approx 45\text{ minutes}$ for the entire 250-iteration production run).

### 3. How Engineers Can Permanently Stop the "Rabbit Chase"

The dossier details four architectural solutions for the upstream library:

1. **Fused Emission & Likelihood Kernels (Triton / CUDA):**  
   Computing quadratic forms $(x_t - A_k x_{t-1} - b_k)^T Q_k^{-1} (x_t - A_k x_{t-1} - b_k)$ inside GPU shared memory and accumulating directly to $(N, T, K)$ eliminates the $(N, T, K, D)$ broadcast intermediate from VRAM ($10\times$ memory reduction).
2. **Mini-Batch Stochastic Variational Inference (SVI) / Online EM:**  
   Replace full-batch Gibbs sampling with mini-batch sequence sampling (e.g. 32 random sequences per step). Transition dynamics ($Ab, Q, \pi$) update continuously with $O(1)$ constant memory regardless of whether the dataset has 10 sessions or 10,000 sessions.
3. **Out-of-Core Streaming Dataset Iterators:**  
   Store coordinate arrays ($Y$) in memory-mapped pinned host RAM and asynchronously stream chunks via double-buffered CUDA streams into JAX.
4. **Multi-GPU Sequence Sharding (`jax.pmap` / `shard_map`):**  
   Because sequences are conditionally independent given $(Ab, Q, \pi)$, distribute sequences across multiple GPUs for linear scaling.
