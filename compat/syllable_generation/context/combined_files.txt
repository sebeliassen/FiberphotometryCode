# Agent Knowledge Transfer: Syllable Generation & Coverage Verification

This document summarizes critical context regarding the Keypoint-MoSeq data pipeline. It is designed to help new agents understand the alignment between Models, Photometry, and Exclusions.

## 1. End-to-End Pipeline Reference
*   **Master Doc**: `syllable_generation/context/DATA_PIPELINE_REFERENCE.md`
*   **Summary**: Details the **Load → Enrich → Attach** pattern.
    *   **Load**: `create_jonathan_sessions.py` / `create_jonathan_amph.py`
    *   **Enrich**: `projects/*/enrich.py` (Applies exclusions and metadata).
    *   **Attach**: `analysis/attach_syllables_kpms.py` (Synchronizes model to photometry).

## 2. Data Resolution & Sampling
*   **Primary Issue**: Models usually run at a lower frequency (e.g., **40Hz**) than Photometry (e.g., **80Hz**).
*   **VFI Scalability**: The **Upsampling Rule** generalizes to any rate difference. If `F_data = R * F_model`, the VFI must be repeated `R` times.
*   **VFI Location**: `syllabizers/keypoint_moseq_syll/amph_project/amph_full_run/video_frame_indexes.npz`.

## 3. Row Alignment (The "North Star")
*   **Golden Rule**: In target pickles (`jonathan_amph_sessions_w_sylls_full_run.pkl`), DataFrame row `k` maps exactly to high-resolution timeline index `k`.
*   **Visual Validation**: `dataset_diagnostics.png` (generated by `plot_exclusion_mismatches.py`) shows perfect overlap between manual exclusion hatches and data NaNs.

## 4. Manual Exclusion Logic
*   **Source File**: `syllable_generation/projects/*/overrides/exclusions.csv`.
*   **Convention**: The `idx:start-end` entries are **Row Indices** into the high-resolution (80Hz) dataframe, not absolute frame numbers in the raw 40Hz video.

## 5. Model Configuration & Metadata
*   **Config**: `syllabizers/keypoint_moseq_syll/amph_project/config.yml` (e.g., `fps: 40`).
*   **Results**: `syllabizers/keypoint_moseq_syll/amph_project/amph_prod_k120k_run_1/model_summary.json` (Iter counts, median duration, kappa).
*   **Batch Run**: `syllabizers/keypoint_moseq_syll/run_batch.sh`.

## 6. Verification Suite
*   **Manual Check**: `syllable_generation/diagnostics/verify_coverage_w_sylls.py`.
*   **Matrix Testing**: `syllable_generation/diagnostics/run_coverage_matrix.sh` (Tests 40Hz vs 80Hz VFI with and without time shifts).
*   **Validation**: Shifting the window by +20,000 frames (using `--shift`) correctly breaks the match, proving the test is sensitive to specific temporal alignment.

## 7. Dataset Types
*   `sanitized.pkl`: Full session data, absolute frame indexing.
*   `w_sylls.pkl`: Behavioral results attached, filtered to valid frames, dense matrix indexing.

## 8. Identifying Exclusions
*   **Green Hatch**: Target exclusion zone.
*   **Red / NaN**: Data removed.
*   **Blue / Value**: Valid data.
*   **Rule**: Exclusions are applied using `subset.isna().any(axis=1)` to ensure if factor signals are targeting the same region, the region is fully masked.

## 9. Timebase Math
*   **Time T** (Seconds) = `Row_Index / Frequency`.
*   For 80Hz: `Rows 0-80` = 1 second.
*   For 40Hz: `Frames 0-40` = 1 second.
*   Alignment requires `Row_Index = Frame_Index * (Frequency_Data / Frequency_Model)`.

## 10. Metadata Enrichment
*   **Source**: `projects/PROJECT/animals.csv` and `sessions.csv`.
*   **Injected into**: `session.metadata` (e.g., `Drug`, `Dose`, `Genotype`).
*   **Avoid**: Do not duplicate these as columns in `all_data_df` to keep the pickle size manageable.

## 11. The "Heuristic"
*   **Origin**: `plot_exclusion_mismatches.py` (and `attach_syllables_kpms.py`).
*   **Logic**: `limit = min(len(df), len(vfi_upsampled))`.
*   **Meaning**: The plotted/verified region is the intersection of the DataFrame length and the Upsampled VFI length. Data beyond this intersection is ignored by diagnostic plots.

## 12. Auto-Masking Interaction
*   **File**: `syllable_generation/projects/.../overrides/auto_mask.npz`
*   **Process**: Auto-masks (low confidence) are applied *before* or *during* dataset creation. Manual exclusions are applied *on top*.
*   **Verification**: The final check (`verify_coverage...`) tests the final state, where Manual Exclusions must correspond to `NaN`s regardless of whether Auto-Masks were also present.

## 13. Column Selection Strategy
*   **Mapping**: `Region` (e.g., L-DLS) -> `Signal Channel` (e.g., signal_3).
*   **Implementation**: `get_signal_col_for_region` in the diagnostic scripts iterates through metadata to find the exact column name associated with the excluded region (handling `_dff` or `_zscore` suffixes).

## 14. 40Hz vs 80Hz Alignment Rule
*   **Reference**: `syllable_generation/analysis/utils/sampling.py` (Implicit).
*   **Relation**: 40Hz Frame `N` corresponds to Time T. 80Hz Row `2N` corresponds to Time T.
*   **Indexing**: When moving between 40Hz VFI and 80Hz DF, multiply indices by 2 (or upsample the array).

## 15. Final "Golden Rules" for Agents
*   **Trust the Plot**: If the user validates a plot, the logic generating that plot (Row k = Index k) is the source of truth, even if it seems counter-intuitive.
*   **Verify by Mimicry**: To build a passing test, mimic the Plot's data transformations (e.g., `Direct Row Indexing`) exactly.

## 16. Case Study: The 40Hz/80Hz Verification Mismatch
*   **The Problem**: Data generated with a **40Hz Model** (`amph_full_run`) but stored in an **80Hz DataFrame** (`w_sylls_full_run.pkl`) caused catastrophic verification failures (0% Coverage) when applying traditional absolute frame lookups.
*   **Observations**:
    1.  **Visuals Pass**: The plotting script (`plot_exclusion_mismatches.py`), which simply plotted `df[0..N]` against `index[0..N]`, showed perfect exclusion alignment.
    2.  **Code Fails**: The verification script (`verify_manual_exclusion_coverage.py`), which tried to map `CSV Index -> 40Hz Frame -> DataFrame Lookup`, failed to find any NaNs.
*   **The Root Cause**:
    *   **Resolution Mismatch**: The CSV indices (`idx:100-200`) were defined on the **Upsampled 80Hz** timeline.
    *   **Translation Error**: Trying to pass these high-res indices through a low-res (40Hz) VFI introduced rounding/padding errors (off by 1 frame), causing the lookup to miss the NaN window entirely.
*   **The Solution**:
    *   We recognized that the `w_sylls` DataFrame is already **filtered and aligned** to the Upsampled VFI.
    *   We implemented **Direct Row Indexing**: Treating the CSV indices as direct slice coordinates for the DataFrame (`df.iloc[start:end]`).
    *   This restored **100% Coverage (0 Mismatches)**.
*   **Takeaway**: When working with `w_sylls` or "Attached" data, the **DataFrame Row Index** is the authoritative timeline key. Do not attempt to reverse-engineer absolute video frames unless necessary.
## 17. Interpolation Safety & Density Correlation
*   **Safety**: Photometry merging uses `interpolate(limit=4)`. This bridges small gaps (jitter) but correctly preserves large Manual Exclusion gaps (>100 frames).
*   **Correlation**: There is a direct correlation between **VFI Breaks** (jumps > 10 frames) and the "Missing Data" delta.
    *   *Observation*: `(Upsampled_VFI_Len - NotNaN_Count) ≈ Total_Gap_Frames_In_VFI`.
    *   *Meaning*: The standard "missing coverage" in the final dataset is almost entirely accounted for by the original gaps in the 40Hz tracking data, confirming that no *extra* data is being dangerously created or destroyed during upsampling.

# Data Pipeline Reference

This document details the end-to-end pipeline for processing fiber photometry and behavioral data, from raw ingestion to the final analysis-ready artifacts.

## Overview
The pipeline follows a **Load → Enrich → Attach** pattern:
1.  **LOAD**: Raw data is ingested into "Dirty" session objects.
2.  **ENRICH**: Metadata (Drug, Dose, Genotype) is injected, and Exclusions are applied to create "Sanitized" objects.
3.  **ATTACH**: Model results (Syllables, Latent States) are attached and synchronized to the 80Hz photometry timeline.

## 1. Loader & Enrichment Phase
**Goal**: Create a clean, metadata-rich session pickle (`_sanitized.pkl`).

### A. Raw Loading
*   **Script**: `loaders/create_jonathan_sessions.py` (IFDN) or `create_jonathan_amph.py` (AMPH).
*   **Process**:
    *   Reads TDT/CSV files.
    *   Aligns Photometry channels.
    *   Detects "Entry Time" (optional).
    *   **Output**: A raw "Dirty" pickle (in-memory or saved as `_dirty.pkl`).

### B. Enrichment (Dirty → Sanitized)
*   **Module**: `projects/PROJECT_NAME/enrich.py`
*   **Logic**:
    *   **Metadata Injection**: Reads `animals.csv` and `sessions.csv` to inject `AnimalID`, `Genotype`, `Drug`, `Dose`.
    *   **Exclusion Application**: Reads `exclusions.csv` to mask invalid data (e.g., fiber detachments).
        *   **Manual Exclusions**: User-defined time ranges (set to NaN).
        *   **Auto Masks**: Automated signal quality checks (set to NaN).
    *   **Flag**: `skip_exclusions=True` produces "Dirty" data; `False` produces "Sanitized".
*   **Output**: `jonathan_PROJECT_sessions_sanitized.pkl` (Saved to `syllable_generation/data/`).

## 2. Syllable Attachment Phase
**Goal**: Merge behavioral model results with the sanitized session data.

### A. The Core Logic (`attach_syllables_kpms.py`)
This script is the unified driver for both IFDN and AMPH datasets.

**Command**:
```bash
python3 analysis/attach_syllables_kpms.py \
    --input data/jonathan_ifdn_sessions_sanitized.pkl \
    --output data/jonathan_ifdn_sessions_w_sylls.pkl \
    --kpms path/to/results.h5
```

### B. Synchronization & Upsampling
The script automatically handles the sampling rate mismatch between the Model (e.g., 40Hz) and Photometry (e.g., 80Hz).

1.  **Load VFI**: Loads `video_frame_indexes.npz` (VFI) which maps every Model Step -> Video Frame.
2.  **Auto-Rate Detection**:
    *   Calculates `Ratio = Session_Length / VFI_Max`.
    *   ** IFDN**: Ratio ≈ 1.0 (Native 80Hz).
    *   ** AMPH**: Ratio ≈ 2.0 (Model 40Hz -> Photometry 80Hz).
3.  **VFI Scaling**: If Rate > 1.0, the VFI indices are scaled (multiplied by Rate) to match the Photometry timeline.
4.  **Syllable Upsampling**:
    *   If using a pre-upsampled VFI (rare/advanced), syllables are upsampled using Nearest Neighbor.
    *   Otherwise, standard VFI scaling handles the alignment.
5.  **Flattening**: Behavioral results are flattened onto the Photometry timeline using the VFI.

## 3. Final Artifact Structure
The output `_w_sylls.pkl` contains a list of `Session` objects with:

*   **`s.metadata`**: Rich dictionary containing all categorical info (Drug, Genotype, Exclusions).
*   **`s.all_data_df`**: A "Slim" DataFrame aligned to 80Hz.
    *   **Columns**: `SystemTimestamp`, `signal_*` (Photometry), `centroid_*` (Kinematics), `syllable`, `frame_index`.
    *   **NO Redundancy**: Metadata is NOT duplicated as columns here.

## Key Features

1.  **Dual Mode Support**: Supports both `peak` (correlation analysis) and `trace` (heatmap analysis) modes via the `--type` argument.
2.  **Drug Splitting**: Correctly handles dataset-specific splitting:
    -   **IFDN**: Single "baseline" condition.
    -   **AMPH**: Splits into "Saline" and "Amphetamine" conditions.

    -   Max Difference: 0.0 for both IFDN and AMPH datasets.

## Implementation Details

### Digestion (`digest_panel_1h_unified.py`)
-   **Trace Digestion**:
    -   Applies 1st-order Bessel High-Pass Filter (1Hz).
    -   Extracts syllable-centered windows (+/- 1.5s).
    -   Computes actual mean response vs. 20x shuffled mean response (jittered onsets).
    -   Saves results as nested dictionaries in `.pkl` files.

### Plotting (`plot_panel_1h_unified.py`)
-   **Trace Plotting**:
    -   Calculates Z-scores using the global shuffle mean and standard deviation: `(actual - shuffle_mean) / shuffle_std`.
    -   Applies row-wise normalization and Gaussian smoothing (sigma=1.0).
    -   Sorts rows by peak activity in the post-onset window.
    -   Generates separate plots for each Drug, Hemisphere, and Fiber Color.

# Panel 1f Replication: Movement vs Syllable Initiation Traces

**Context**: This documentation details the logic and implementation for replicating "Panel 1f" from the Datta Lab's methodology (e.g., Markowitz et al., 2023). The goal is to visualize dopamine (DA) transients aligned to the onset of spontaneous syllable usage versus movement initiations.

## Pipeline Modes (Fidelity Tiers)

To ensure both visual clarity and statistical rigor, the pipeline supports three processing modes controlled via a command-line argument to `run_replication_pipeline.sh`:

### 1. Mid-Fi (Selected Standard)
*   **Command**: `./run_replication_pipeline.sh midfi`
*   **Logic**:
    *   **Filtering**: None. Traces are kept "raw" (no 1Hz hipass) to preserve signal smoothness and avoid high-frequency noise artifacts ("scribbles").
    *   **Normalization**: **Z-to-Shuffle**. The observed mean trace is renormalized against the shuffle distribution:
        $$Z_{shuffle} = \frac{\mu_{obs} - \mu_{shuffle}}{\sigma_{shuffle}}$$
    *   **Units**: "DA (Shuffle STDs)". This aligns the Y-axis magnitude with published figures.
*   **Output**: `plots_midfi/`

### 2. Hi-Fi ("Pixel Perfect")
*   **Command**: `./run_replication_pipeline.sh hifi`
*   **Logic**:
    *   **Filtering**: **1Hz Bessel High-Pass Filter** (2nd order). Strictly follows the Datta lab methods to remove baseline drift.
    *   **Normalization**: Z-to-Shuffle.
*   **Trade-off**: While methdologically identical to the original paper, on this specific dataset, the high-pass filter exacerbated the appearance of the noise floor, creating distracting "scribbly" traces.
*   **Output**: `plots_hifi/`

### 3. Standard
*   **Command**: `./run_replication_pipeline.sh std`
*   **Logic**:
    *   **Filtering**: None.
    *   **Normalization**: Standard Z-Score (dF/F).
*   **Output**: `plots_std/` (or default `plots/`)

## Glossary of Terms

### Alignment Events
*   **`syllables_offline`**: Syllable onset timestamps derived from the **full, bidirectional** VFI (Video Frame Index) analysis. Because the model analyzes the entire session file at once, it can "see the future," providing the most accurate ground truth for when a behavioral syllable actually began. This is preferred over "online" (real-time) detection for alignment.
*   **`movement`**: A control metric. These are initiation indices calculated based on the velocity derivative crossing a threshold (Markowitz 2022 logic).

### Processing Steps
*   **Aggregated Region/Hemi**: Results are split by Genotype (WT/KI) -> Drug (Saline/Amph) -> Brain Region (DMS/DLS/VS) -> Hemisphere (Left/Right/average).
*   **Green Fiber Focus**: Only signals with `orig_letter='G'` (Green/GCaMP) are processed.
*   **Flat Shuffle Bands**: The 95% Confidence Interval for the shuffle distribution is visualized as a static horizontal band (mean of 2.5% and 97.5% percentiles across the window) rather than a time-varying envelope, improving legibility.

# Syllable Weaving Strategy

## 1. Overview
This document details the architectural shift from a **Filtered** output (where `NaN`s are deleted) to a **Full-Session / Weaved** output (where `NaN`s are preserved in a full-length dataframe).

*   **Old Strategy**: Filter Photometry to match valid Tracking frames.
    *   *Result*: Clean dataset, but lost time information (gaps removed).
*   **New Strategy**: **Syllable Weaving**.
    *   *Result*: Maintain the original, absolute Photometry timeline. "Weave" valid syllables into it. Gaps in tracking become `NaN`s in the Syllable columns.

## 2. Why "Weave" (Compute First, Join Later)?
Keypoint-MoSeq (the modeling library) requires contiguous, valid data to function correctly (PCA, AR-HMM). It cannot handle `NaN`s natively.
Therefore, we must:
1.  **Extract Valid Chunks**: Use VFI to pull only valid data.
2.  **Compute Syllables**: Run the model on these valid, condensed chunks.
3.  **Weave Back**: Take the resulting syllables and place them back onto the original timeline using the VFI as a "coordinate map".

## 3. Sampling Rates & Upsampling
The weaving logic differentiates between projects based on the native recording rate:

*   **IFDN (80Hz Native)**:
    *   **VFI**: Absolute 80Hz indices (Step = 1).
    *   **Model**: 80Hz output.
    *   **Logic**: 1:1 Mapping. No extra `ffill` required for upsampling.
*   **AMPH (40Hz Native -> 80Hz Weaved)**:
    *   **VFI**: Originally 40Hz (detected by `migrate_legacy_vfi`).
    *   **Scaling**: Indices are doubled (Step = 2) to match 80Hz timeline.
    *   **Logic**: 1:2 Expansion. Model frame `i` covers two 80Hz frames via `ffill`.

## 4. Interpolation & NaN Expectations
We use **Linear Interpolation (`limit=4`)** on the Photometry.
*   **NaN Signature**: Peaks at NaN run lengths **7** and **3** occur in both projects. This is a mathematical artifact of the `limit=4` interpolator bridging small gaps caused by 40Hz-locked auto-masking on an 80Hz timeline.
*   **Verdict**: These specific NaN patterns are **EXPECTED** and verified as safe.

## 5. Summary Workflow
1.  **Mother Index**: Initialize dataframe to length `n_frames` (Video Reference).
2.  **Scale VFI**: Convert relative/legacy VFI to absolute 80Hz indices.
3.  **Place**: Map model results onto the timeline using scaled VFI coordinates.
4.  **FFill**: Apply forward fill to syllables (to cover 1-frame gaps in 40Hz projects).
5.  **Output**: `all_data_df` containing aligned behavioral and neural data.

## 1. Core Paradigm: "Ground Truth VFI"
*   **Definition**: The Video Frame Index (VFI) (`video_frame_indexes.npz`) **ALWAYS** refers to the absolute frame numbers (0, 1, 2...) of the original, high-frequency (80Hz) video.
*   **Invariant**: Even if the model is trained on downsampled data (e.g., 40Hz), the stored VFI maps those downsampled steps back to their original absolute positions (e.g., `0, 2, 4...`).
*   **No "Rate Detection"**: Downstream analysis scripts must **NEVER** attempt to guess a downsampling rate to multiply indices. They should trust the VFI as absolute truth.

## 2. Legacy Data Handling
*   **The Artifact**: Old `.pkl` files and `.npz` files produced before Jan 2026 often contain "Relative/Downsampled" indices (0, 1, 2... for a 40Hz stream).
*   **The Solution**: `syllable_generation/analysis/utils/legacy_support.py`.
    *   **Heuristic**: If `VFI_Max < (Session_Length / 1.5)`, it is flagged as Legacy.
    *   **Migration**: It is scaled on-the-fly (e.g., x2.0) to convert it to Ground Truth.
*   **Rule**: All legacy logic is isolated in `legacy_support.py`. Do not re-introduce "rate args" into main functions.

## 3. Analysis Pipeline Flow
The key script `attach_syllables_kpms.py` follows this strict flow to guarantee alignment:

1.  **Load Data**: Sessions (Photometry) + KPMS Results + VFI.
2.  **Migrate VFI**: `legacy_support.migrate_legacy_vfi()` ensures VFI is absolute Int64.
3.  **Align**: `sampling.build_aligned_dfs()`:
    *   Maps Results to VFI.
    *   **Densification**: Uses `ffill` (forward fill) to bridge gaps between VFI indices (e.g., filling index 1 between 0 and 2).
    *   **Full Coverage**: Forces the DataFrame index to be `0` to `Photometry_Length`.
    *   **Result**: `all_data_df` matches `photometry` 1:1.

| `analysis/attach_syllables_kpms.py` | **Orchestrator**. Wiring it all together. |

*   **Coverage**: Verified that the new pipeline recovers frames at the start/end of sessions that were previously clipped, ensuring no data loss.

3.  **Nullable Integers**: Use `Int64` (capital I) for syllable columns to gracefully handle the `NaN`s that naturally occur during aligning/padding.
# VideoGen & Synchronization Verification

**Goal**: Explain the architecture of the Video Generation module (`videogen`) and how it serves as the primary verification tool for Syllable-Video synchronization.

## 1. Overview
The `videogen` module produces composite videos (e.g., Side-by-Side or Trio layouts) that visualize the alignment between:
1.  **Behavior Video** (Raw AVI)
2.  **Syllable Data** (Keypoint-MoSeq output)
3.  **Photometry Signals** (dF/F traces)

It is the visual proof that the "Syllable Weaving" strategy works as intended.

## 2. Synchronization Architecture
The underlying data comes from the "Weaved" pickles (`w_sylls.pkl`).
*   **The Invariant**: Efficiency is secondary to alignment. The dataframe provided to `videogen` is **Time-Locked** to the video frames.
*   **1:1 Mapping**: `df.iloc[i]` corresponds exactly to Video Frame `i`. This is achieved by anchoring the dataframe index to the video's `n_frames` metadata.
*   **Missing Data**: Frames where tracking or photometry is missing are preserved as `NaN` rows, keeping the absolute timeline intact.

## 3. Visual Verification Tools
To empirically prove this synchronization, the module offers specific verification flags:

### Tracking Overlays (`--show-tracking`)
Draws raw tracking data from the dataframe directly onto the video grid.
*   **Red Dot**: `centroid_x`, `centroid_y` from the dataframe.
*   **Green Arrow**: `heading` from the dataframe.
*   **Verification**: If the Red Dot is on the mouse, the **Syllable is Valid**. (Since Syllable and Centroid share the same row/index).

### Heading Correction (`--flip-heading`)
*   **Problem**: Coordinate system mismatches (e.g., Model 0° = Right, CV2 0° = Left) can cause the heading arrow to point backwards.
*   **Solution**: The `--flip-heading` flag adds 180° ($\pi$ radians) to the visualization angle. It is a display-side correction that does not alter data.

## 4. Key Logic Concepts

### A. Sticky Syllable Display
To prevent visual flickering when a specific syllable's trajectory plot (PDF) is missing:
*   **Logic**: If `Syllable X` is requested but `SyllableX.pdf` is missing, the generator continues to display the **Last Valid Syllable Image**.
*   **Benefit**: Maintains visual continuity during rapid transitions or sparse plot coverage.

### B. Real-Speed Playback
Because the source data (80Hz) often exceeds standard video framerates (30Hz), a 1:1 render results in slow-motion output.
*   **Sampling**: The composer calculates a `stride = Source_FPS / Target_FPS` (e.g., 2.67).
*   **Execution**: It samples every ~$N$-th frame from the dataframe and seeks the video player to match.
*   **Result**: 1 second of experiment time equals 1 second of video playback.

## 5. Usage Reference

**Standard Verification Command:**
```bash
python syllable_generation/videogen/main.py \
    --pkl <path_to_pkl> \
    --output <dir> \
    --session 0 \
    --trio \
    --show-tracking \
    --flip-heading \
    --test-syllable-mode
```

*   `--trio`: Generates the full 3-panel layout.
*   `--test-syllable-mode`: Automatically finds the most interesting window (many syllable changes) to render.
# Weaved Coverage Verification

**Goal**: Establish the verification status of "Weaved" 1-to-1 Photometry pickles and define the correct diagnostic logic for future data.

## 1. Overview
As of Jan 2026, the pipeline uses the **Syllable Weaving** strategy, where full-session photometry pickles are saved (preservings gaps/NaNs). Verification confirms that manual exclusions from `exclusions.csv` are applied correctly to these absolute timelines.

## 2. The "Direct Indexing" Invariant
A key finding during verification (covering both IFDN and AMPH projects) is that the manual exclusion indices refer to **Absolute Photometry Frames** directly.

*   **Logic**: Exclusions (`idx:START-END`) map 1:1 to the dataframe indices.
*   **No Translation**: Unlike older "Filtered" streams, these indices do **NOT** require translation via VFI (Video Frame Index).
*   **Scaling**: Since the pickles are 80Hz "Weaved", no further scaling (e.g., 40Hz -> 80Hz) should be applied to the CSV indices.

## 3. Verification Status (Baseline Jan 9, 2026)
Formal verification was conducted on the latest production pickles using `verify_weaved_coverage.py`.

| Project | Target Pickle | Pass Rate (Baseline) | Mode | 
| :--- | :--- | :--- | :--- |
| **IFDN** | `jonathan_ifdn_sessions_w_sylls.pkl` | **100% (12/12)** | `--direct --disable-scale` |
| **AMPH** | `jonathan_amph_sessions_w_sylls.pkl` | **100% (21/21)** | `--direct --disable-scale` |

### **Cardinality & Anchoring (The "Mother Index")**
A significant resolution was achieved regarding session lengths. 
*   **The Problem**: Some IFDN sessions were shorter than their video recording because they were clipped to the tracking end (VFI Max).
*   **The Fix**: All standard pickles are now **Anchored to `n_frames`** from the primary video reference.
*   **Result**: The dataframe index is identical to the video frame index. Gaps at the start or end are preserved as `NaN` syllables, ensuring absolute time-locking.

### Sensitivity Results
Both projects passed sensitivity checks (checking data immediately after exclusions). Failures in sensitivity metrics were attributed to session boundaries (end-of-file padding) or natural tracking sparsity, not alignment errors.
